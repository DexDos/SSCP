>[!question]- Null-byte
>**Null bytes** — in c (The language Linux kernel is written on) strings do not have a fixed length. They are called *null-terminated strings*:
>```
>symbols:
>	 'H' 'e' 'l' 'l' 'o' \x00 
>ASCII: 
>	0x48 0x65 0x6c 0x6c 0x6f 0x00
>```
>
>When reading function is performing a by-byte reading (or whatever) it is actually waiting for the `\x00` to appear. The rest of the content of a line is pretty much left not read. 
>
>When a `strcpy` copying a vulnerable buffer, the buffer must not contain null-bytes in order to perform a classic Buffer Overflow attack.  
>
>There are multiple ways to exploit such a vulnerability. For example, [msfvenom encoders](msfvenom.md) are specifically designed to paste the entire malicious code into a vulnerable buffer.  

>[!warning]- The trick
>The attack of contamination with a null-byte performed is a way to bypass WAF. Basically, WAF searches for specific patterns, like the direct `%00` passing attempt. However, by passing a `%2500` pattern we are aiming to bypass a first decoding sequence. 
>##### ASCII
>- `%00` — is getting converted into an escape sequence `\0`
>- `%25` — is getting converted into a `%` character. 
>So by writing `%2500` we are heading towards `%2500`$\rightarrow$`%00`$\rightarrow$`\0`
>##### Backend handling
>A high-level language will read the filename "as is": `filename = ".env\0.md"`
>And then will perform a basic check if the string ends with allowed extensions:
>```
> if (filename.endsWith(".md")) { 
> 	downloadFile(filename); 
> }
>```
>##### Language core reading
>As Firefox uses *SpiderMonkey* (Chrome – *V8*) JS engine, which is written in C, the pattern is basically aimed to exploit the null-byte syntax in C (which is `\00`). It reads the filename by one char and searches for the null-byte, which is typically ending strings. So that `".env\0.md"` will be read as `.env`.
>
>However we have retrieved these files through an ftp server. This means it is either written in C (or C++), or it utilizes system calls, which eventually is gonna cut it. 
>
>Alternatively, this could have been a server written in python (for example), which stores strings as immutable UNICODE objects with the string size value, link counter (in order to know whether the string could be passed to a garbage collector) and so on. Had this been the case, even though python is written in C++, we would not be able to retrieve any files ever which way by utilizing bare null-byte injection.
