## Steps
Let's use an *SQLI* to retrieve information about users table in order to find an email, which belong to Bjoern:

```
'))+UNION+SELECT+username,email,totpSecret,role,id,6,7,8,9+FROM+users;--
```

- The `))` symbols are needed because of the query syntax
- `username,email,totpSecret,role,id,6,7,8,9` columns selected are used because of the `UNION` operator, which enforces us to use the number of columns, which the first query fetches from the `products` query, which is `*` — asterisk symbol ( all options available ).
- `;--` — comments out the rest of the query

> Assignments [5](5.md) and [6](6.md) feature the main principles and structure of the *SQLI* used.

So the result is quite promising. We have found two  tables: `SecurityAnswers` and `SecurityQuestions`.

`SecurityAnswers` table consists of:
- `UserId` — Foreign key for `id` column of `users` table
- `SecurityQuestionId` — Foreign key for `id` column of `SecurityQuestions` table
- `id` — Primary key; the record identifier
- `answer` — the answer
- `createdAt` — date of creation
- `updatedAt`  — date of an answer replenishment

`SecurityQuestions` table consists of:
- `id` — Primary key; the question identifier
- `question` — the text of the question
- `createdAt` — date of creation
- `updatedAt`  — date of an question disposition review

So that we are interested in `SecurityQuestionId`, `UserId` and potentially `answer` columns of the `SecurityAnswers` table and `id` and `question` of `SecurityQuestions`. The `answer` is likely (it has to, actually) to contain a preserved hash, but not the answer itself.
